# Agent Note: 会话标题栏把模式启动到新会话

Status: implemented

[English](2026-08-17-session-header-preset-launcher.md) | 中文

## 问题

会话标题栏此前仅以静态文本显示当前 agent preset。即使用户已经知道标准、PTC、极简和创造模式的存在，也必须离开当前对话，或先进入尚未配置的新建会话流程，才能看到各模式的作用。把该标签改成原地切换并不安全：运行中会话的历史由原来的工具与提示词产生，第一次轮次结束后宿主也会拒绝替换。

## 决策

标题栏标签改为基于共享 agent-preset 名单的菜单入口。每一行都显示本地化名称、单句用途说明，以及明确表示「当前会话」或「新会话」的徽标。触发按钮仍显示当前可见会话所记录的 preset，因此打开菜单绝不会改变当前对话声称运行的模式。

选择其他行时，入口会在 `AgentPresetSeatController` 上暂存该 preset，并调用既有的工作区 `startSession()` 流程。已有工作区的对话会打开或复用其空白会话，并由现有会话列表订阅器应用暂存值；没有可用工作区时，外壳进入新建会话界面，同时保留已暂存的选择。选择当前行只会关闭菜单。

入口与共享菜单基础组件使用短时长的位移、透明度、光晕和滤镜过渡，为悬停、展开与按压提供反馈。`prefers-reduced-motion: reduce` 会移除空间位移与按压动作，同时保留颜色和状态变化。

本决策只改变[逐会话 preset 架构](../architecture/2026-08-03-per-session-agent-presets.md)所描述的入口，不改变「已开始的会话绝不采用另一份组装」这条规则。

## 考虑过的替代方案

**原地切换当前可见会话。** 否决，因为宿主在一个轮次结束后拒绝不同 preset 是正确行为：已经记录的工具调用、提示词贡献和可用能力必须能在产生它们的那份组装下重建。

**打开设置页而非直接展示名单。** 否决，因为 General 设置改变的是部署默认值，不能表达用户「立即以所选模式开始一次对话」的意图，而且会把模式说明藏在无关导航之后。

**另建一套标题栏专用名单控制器。** 否决，因为新会话 seat 已经负责跨工作区创建与空白会话复用的暂存和应用。并行控制器会复制生命周期规则，并可能在暂存值何时被消费这一点上产生分歧。

## 后果

用户可在看见当前模式的位置直接了解其他模式，每个非当前选择也都有即时且安全的结果。当前对话仍保留在会话列表中，并保持自己的 preset。选择模式可能发生导航，因为启动新会话正是该操作声明的效果；菜单文案会在点击前明确说明这一点。

组件覆盖固定模式说明、当前/新会话徽标、选择当前行不执行操作，以及选择其他行的派发。插件覆盖固定共享名单、暂存 preset、引导提示和一次工作区启动。
